## Summary

Routes `POST /auth/login` through strict SIWE (EIP-4361) verification when the signed message has the SIWE envelope, while retaining the legacy wallet-signature path for backward compatibility. Fixes #843.

### What changed

- **`src/auth/auth.service.ts`**
  - `generateChallenge()` now persists the challenge address and, for SIWE challenges, the issued domain, URI, chain ID and statement alongside the nonce. This is the server-side policy used at login, so a valid challenge returned by the API can be verified against exactly what was issued.
  - `login()` detects the format from the message content (SIWE envelope parsed via `SiweService.parseMessage`, never from a client-supplied flag). Legacy signatures are still verified with `ethers.verifyMessage`; SIWE signatures are verified with `SiweService.verifySiwe()` using the issued/challenge and configured domain, origin, supported chains, statement and allowlists.
  - The verified signer address (not the submitted `address` field) is bound to the stored challenge, and is the principal used for wallet lookup and token issuance.
  - Malformed SIWE messages go through the SIWE verifier and fail closed — never downgraded to legacy verification; a legacy message presented against a SIWE challenge is rejected as a downgrade.
  - All failures still collapse to the same external `401 Invalid credentials`; only redacted reason codes are logged. Nonce consumption uses one shared fail-closed contract for both formats.
  - Fixed the broken `AUTH_GENERIC_FAILURE_MESSAGE` import that previously turned every login failure into a `ReferenceError` instead of the constant-shape 401.
- **`src/redis/redis.service.ts`** — added `consume(key, expectedValue)`: an atomic GET+DEL Lua operation that fails closed when Redis is unavailable or the record changed, used by both login formats to prevent concurrent replay.
- **`src/auth/services/siwe.service.ts`** — alignment of internal failure codes with the existing verifier contract (`INVALID_SIGNATURE`, `ADDRESS_MISMATCH`) and numeric coercion of `AUTH_NONCE_TTL_MS` when building expirations; external responses are unaffected.
- **`src/auth/auth.controller.ts` / `src/auth/README.md`** — document content-based format detection, strict EIP-4361 checks, no legacy downgrade, and the additional health feature flag.
- **`src/auth/auth.service.siwe.spec.ts` (new)** — integration-level coverage with real `SiweService` and ethers-signed messages: happy path, policy/tampering rejection (domain, URI origin, chain, statement, nonce, issued-at, expiration), wrong signer, no legacy fallback, ignored client format hints, legacy compatibility, shared atomic consumption, Redis failures, concurrency and generic 401s.
- **`package.json`** — repaired the malformed `@anthropic-ai/sdk` key and restored the four manifest entries that were missing relative to `package-lock.json`, so `npm ci` / Jest can parse and resolve the project.
