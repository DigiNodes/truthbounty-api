## Summary

Replace hard-coded Sybil accuracy counters with a deterministic, read-only projection of finalized canonical claim history. Production `gatherSignals()` now derives `claimsVotedOn` / `claimsCorrect` from the approved on-chain event read model instead of returning zeros.

Closes #855

## Changes

- Added `ClaimAccuracyService` (`src/sybil-resistance/claim-accuracy.service.ts`) with a pure `projectClaimAccuracy()` projection over `v2_canonical_events`, bounded by `v2_event_checkpoints` and the pinned chain/release/deployment from `contracts/manifests/optimism-sepolia.release.json`.
- Evaluations are `VerificationRecorded` events from currently linked wallets; canonical outcomes come only from finalized `VerdictSettled` events, with `DisputeRaised` / `DisputeResolved` / `DisputeExpired` handled deterministically. Abstentions, own claims, unverifiable authors, unfinalized/reverted/disputed/unknown outcomes and duplicates are excluded.
- Added provenance for the accuracy feature (status, chain/release, contract, finalized block, observation time, exclusion counters, unavailable reason). Missing and unavailable history is reported honestly; `failClosedOnMissing` / `failClosedOnStale` reject unavailable data instead of treating it as verified zero activity.
- Registered the service and canonical-event/checkpoint repositories in `SybilResistanceModule`; wired derivation into `SybilResistanceService.gatherSignals()`.
- Model-level missing features (e.g. activity below `minClaimsForAccuracyScore`) now propagate into score details / fail-closed checks.
- Updated `docs/SYBIL_RISK_SCORING_PROVENANCE.md`.
