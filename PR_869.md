## Summary

PREWAVE-BE-166 — staking-derived Sybil signals are now bound to an approved canonical chain/deployment authority and a finalized block checkpoint.

- Added `SybilStakingAuthorityService`: resolves the authority **server-side** from the approved runtime binding plus the provenance registry (`v2_contract_artifacts` with `isApproved`, artifact checksum/deployment block, and `v2_event_checkpoints` finalized block/hash). Missing or inconsistent binding, unapproved artifact, missing/regressed finalized checkpoint, or missing finalized block hash fail closed.
- Caller-supplied `RecomputeScoreOptions.authority` is never sufficient. If it is invalid or conflicts with the registry authority, the staking feature is treated as missing; no caller metadata can widen the query.
- `computeSybilScore()`, `recomputeScore()`, and `getPublicSybilScore()` now use the same resolver; the public path no longer re-gathers signals with a second, unbound query.
- `StakeEvent` gained nullable `chainId`/`contractAddress` columns (reversible migration `1793200000000-AddStakeEventChainScope`) and `StakingSyncService` stamps them from the approved chain/deployment config. Unscoped legacy rows can never match the query.
- The production staking query is constrained to `chainId`, `contractAddress`, and `[deploymentBlock, finalizedThroughBlock]`. Without a valid authority no `StakeEvent` query is executed and `staking` is recorded as missing (`authorityError: authority_unavailable`), so strict mode applies `MissingFeatureException`.
- Each calculation record stores the exact `stakingCheckpoint` (chain, release, artifact hash, deployment block, finalized block, finalized block hash, source and SHA-256 `checkpointKey`) at the top level, in `featureProvenance.staking`, and in the provenance digest.
- `getLatestSybilScore()` / `getLatestSybilScores()` compare the stored checkpoint key with the current registry checkpoint and deterministically recompute stale scores (finality advance, checkpoint regression, reorg hash change) instead of presenting them as current.
- Public score serialization remains sanitized: only the digest and aggregate summaries are exposed, never wallet addresses, raw events, nullifiers or proofs.
- Fixed the pre-existing malformed `@anthropic-ai/sdk` key in `package.json` (invalid JSON prevented Node/Jest from starting at all) and documented the new invariants in `docs/SYBIL_RISK_SCORING_PROVENANCE.md`.
