## Summary

Fixes reorg rollback resetting governance proposals to `PENDING` when a `VoteCast` (or a role-change event) happens to be the last event mentioning the proposal. Proposal state is now reconstructed **only** from canonical lifecycle events at or below the rollback checkpoint, and the whole rollback runs in one database transaction.

Closes #890

## Changes

- `src/v2/governance/governance-projection.service.ts`
  - Added a single canonical lifecycle event set (`ProposalCreated`, `ProposalQueued`, `ProposalExecuted`, `ProposalCanceled`, `ProposalExpired`) reused by forward projection and rollback; `VoteCast` / `RoleGranted` / `RoleRevoked` stay in their separate vote and audit-trail projections.
  - Replaced the fragile `payload LIKE '%"proposalId":"..."%'` lookup with a typed, chain-scoped predicate: `e.payload->>'proposalId' = :proposalId` on PostgreSQL and `CAST(json_extract(e.payload, '$.proposalId') AS TEXT) = :proposalId` on SQLite, with a TypeScript-side fallback for drivers without JSON operators.
  - The lookup is also scoped by governor/deployment address, uses numeric block ordering plus `logIndex` (and `txHash` as a deterministic tie-breaker), and re-checks all constraints in memory so a vote can never be selected as the state source.
  - Reconstructs state from the latest surviving lifecycle event; if no `ProposalCreated` event remains, the proposal and all of its actions are deleted.
  - `mapEventToState()` returns `null` for non-lifecycle events instead of silently defaulting to `PENDING`.
  - Rollback (vote/role deletes, proposal state update, action rebuild) is wrapped in `EntityManager.transaction()` using transaction-scoped repositories, with state and actions derived from the same canonical creation event.
- `src/v2/governance/__tests__/governance-projection.reorg.spec.ts` (new)
  - 9 regression tests covering: queued/executed proposals kept when a later vote is the last event, restoring the preceding lifecycle state after a rolled-back transition, votes and role changes never determining state, deletion when `ProposalCreated` is gone, deterministic same-block/logIndex ordering, typed predicate and chain/governor scoping, and atomicity on transaction failure.
