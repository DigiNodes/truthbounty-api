## What changed

Closes #889 — the V2 governance projection now stores the actual Governor
proposal hash instead of the event's description hash.

- `ProposalDecoderService.computeProposalHash()` now encodes the canonical
  `address[] / uint256[] / bytes[] / bytes32` payload with `AbiCoder` and hashes
  the raw ABI bytes with `keccak256` (no more `id()` over a UTF-8 string).
- Added strict fail-closed validation of `targets`, `values`, `calldatas` and
  `descriptionHash`, plus `verifyProposalHash()` which cross-checks the computed
  hash against the `proposalId` emitted on chain. A formula or ABI from a wrong
  Governor release therefore cannot produce an accepted hash.
- `projectProposalCreated()` requires an approved governor artifact for the
  event's chain/deployment with a matching artifact version, verifies the hash
  before any write, and marks the event `staleArtifact` (no fabricated hash)
  when validation, artifact binding or the proposal-id cross-check fails.
- `descriptionHash` and `proposalHashScheme` are stored as separate columns from
  `proposalHash`; chain, governor address, artifact version and the originating
  `(txHash, logIndex)` stay on the row as provenance. The read API exposes the
  new fields. Migration `1793400000000` blanks legacy `proposalHash` values and
  moves them to `descriptionHash` (reproject to restore correct hashes).
