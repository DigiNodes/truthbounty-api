## PREWAVE-BE-161 — Derive governance proposal and vote records from verified identity and canonical events

### Problem

The legacy `POST /governance/proposals` and `POST /governance/proposals/:id/votes`
endpoints accepted `proposer`, `voter` and `weight` from the request body and
`GovernanceService` wrote those values straight into local tables. A valid JWT
only proved authentication — not control of the supplied wallet, contract-level
voting power, or the existence of an on-chain proposal/vote. Local totals were
incremented from client input, so backend-authored participation could be
presented as authoritative.

### Fix

- **Identity binding.** `create()`/`castVote()` take the address from the
  verified JWT principal (`request.user.address`) only. `proposer`, `voter` and
  `weight` were removed from the DTOs; a missing principal fails closed.
- **Canonical evidence service** (`GovernanceEvidenceService`) resolves only a
  `(chainId, txHash, logIndex)` pointer and re-derives every governance field
  from a canonical log. It fails closed with stable codes for wrong chain,
  missing/reorged log, unexpected event name, unapproved deployment, artifact
  drift, unsupported ABI event, pre-deployment logs, missing/invalid finalized
  checkpoint, and proposer/voter/proposal mismatch.
- **No client authority.** Support mode and exact uint256 weight come from the
  `VoteCast` payload (stored as decimal string, never a JS number). Request
  metadata cannot affect them.
- **Canonical identity & rebuildable totals.** Votes carry chain, governor,
  canonical proposal id, tx hash, log index, block and artifact version with a
  unique index on that identity. `rebuildProposalTotals()` /
  `rebuildAllProposalTotals()` recompute counts and weight sums from the
  canonical vote rows; `reconcileReorg()` removes projections above the new
  head and demotes reorged proposals to drafts.
- **Draft labelling.** Proposals now expose `recordKind` (`OFFCHAIN_DRAFT` /
  `CANONICAL`) and `dataState` (`DRAFT` / `FINALIZED`). Drafts cannot be
  activated, executed or voted on as protocol proposals; activation/execution
  remain indexing labels for canonical rows only, with contract execution as
  the source of truth.
- Governance event names were added to the canonical event schema registry so
  `ProposalCreated`/`VoteCast` can actually be normalized and used as evidence.
- Migration `1793200000000-GovernanceCanonicalProvenance` adds the columns,
  backfills legacy rows as drafts, converts vote weights to decimal strings and
  creates the canonical-identity unique index.
- Documentation: `docs/GOVERNANCE_CANONICAL_PROVENANCE.md`.
