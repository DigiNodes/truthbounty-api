## Summary

The V2 governance timelock endpoint derived `queuedAtBlock` from the current proposal state plus action-row existence, and all terminal blocks from the single mutable `stateChangedAtBlock` field. Once a proposal advanced past QUEUED, its queue block was lost and a queued proposal with no action rows reported nothing.

This PR introduces an immutable, append-only canonical lifecycle history and builds the timelock projection from it.

- New `GovernanceProposalTransition` entity (`v2_governance_proposal_transitions`) with full provenance: chain, emitting contract, proposal ID, event name/state, ETA, transaction hash, log index, block number, block timestamp and artifact version. Unique on `(chainId, txHash, logIndex)` for idempotent replay.
- `GovernanceProjectionService.projectStateTransition()` now appends one transition row per canonical `ProposalQueued` / `ProposalExecuted` / `ProposalCanceled` / `ProposalExpired` event; duplicate replays are no-ops and stale-artifact events write nothing.
- `rollbackAboveBlock()` deletes only transitions above the affected block, so replay rebuilds lifecycle history deterministically without touching canonical events below it.
- `GovernanceReadService.getTimelock()` reads the four `*_AtBlock` fields from that history (ordered by block, then logIndex) and never consults action rows or infers state. The response also includes a `transitions` array carrying full event provenance, kept semantically distinct from the current `state`.
- Added a reversible TypeORM migration and registered the entity in `GovernanceV2Module`.
