# PREWAVE-BE-136 — Derive safe and finalized checkpoints from canonical chain heads

Closes #839

## Problem

`CanonicalEventsService.ingest()` advanced `v2_event_checkpoints.lastSafeBlock` to the block of the log just ingested and computed `lastFinalizedBlock` as `eventBlock - confirmations.finalized`. That mixes ingestion progress with chain finality: a still-reorgable block could be advertised as safe, and the finalized watermark could lag or overstate the provider's actual finality.

## Changes

- Added `src/v2/events/chain-heads.ts`: the authoritative `latest`/`safe`/`finalized` provider-tag head source (`RpcChainHeadsProvider`) plus fail-closed `validateChainHeads()` (chain scope, structure, `finalized <= safe <= observed`, freshness, hash format).
- `canonical-events.service.ts`: ingestion now persists `lastProcessedBlock` from the log, but advances `lastSafeBlock` / `lastFinalizedBlock` **only** from validated provider heads — clamped to `finalized <= safe <= observed`, monotonic, and transactional with the event write. Missing/invalid/stale/regressing/contradictory heads leave the finality watermarks and their provenance untouched.
- `event-checkpoint.entity.ts` + migration `1792500000000-DeriveCheckpointsFromChainHeads`: distinct persisted progress/safe/finalized facts, plus `observedHead`, `headSource`, `headsObservedAt`, and block-hash provenance.
- `projection-freshness`: exposes `finalitySource` / `headsObservedAt`, treats zero-height or provenance-less checkpoints as degraded (`finality-unavailable`, `safe-unavailable`, `finality-provenance-missing`).
- Reorg/rollback and the existing finalized-cursor authority are unchanged; this uses the single durable checkpoint at `v2_event_checkpoints` and reads the provider finality tags, not a second cursor.
- Docs: `docs/indexer-runbook.md` updated with the new fields and fail-closed policy.
- Build fix: restored the missing quote in `package.json` (`@anthropic-ai/sdk`) so `npm ci` can parse the manifest.

## Acceptance criteria

- [x] Ingestion progress, safe head, finalized head are distinct persisted facts.
- [x] Safe/finalized come from provider finality tags, never from an event block or confirmation subtraction.
- [x] Unavailable or inconsistent provider finality fails closed and is visible in freshness output.
- [x] No unfinalized event is labelled safe/finalized merely because it was ingested.
- [x] Reorg/regression/restart preserve monotonic checkpoint invariants (Postgres test gated on `CHECKPOINT_TEST_DATABASE_URL`).
- [x] Documentation and tests match the Optimism/EVM provider finality policy.
