## Summary

`ProposalDecoderService.computeProposalHash()` ABI-encodes the Governor call tuple and then hashes the **UTF-8 characters of the 0x-prefixed hex string** via ethers `id()`. Solidity's `hashProposal()` hashes the **raw ABI-encoded bytes** with `keccak256`, so valid `ProposalCreated` events can fail the API's cross-check.

This PR hashes the raw bytes with `keccak256(getBytes(encoded))` and adds fail-closed validation plus a non-authoritative, provenance-bearing cross-check API.

## Changes

- `src/v2/governance/proposal-decoder.service.ts`
  - Replaced `id(encoded)` with `keccak256(getBytes(encoded))`.
  - Exported `PROPOSAL_HASH_ABI_TYPES = ['address[]', 'uint256[]', 'bytes[]', 'bytes32']` — the OZ Governor `hashProposal()` field order.
  - Validate before hashing: array presence and equal lengths (non-empty), 20-byte addresses with EIP-55 checksum, canonical decimal uint256 values within range, even-length 0x calldata, and 32-byte description hash.
  - Added `crossCheckProposalHash(input, observedHash, provenance)` returning `computedHash`, `observedHash`, `matches`, `abiTypes`, `provenance`, and `authoritative: false`. It validates the chain against `ALLOWED_CHAIN_IDS` and requires release/deployment/artifact provenance. It is a read-only cross-check and never writes proposal state.
- `src/v2/governance/__tests__/proposal-decoder.service.spec.ts`
  - Golden vectors independently computed with a standalone Keccak-256 implementation and cross-verified against ethers.
  - Distinct proposals produce distinct hashes; mutating each of the four encoded fields changes the hash.
  - Explicit regression test: `id(encoded)` (UTF-8 hash) differs from `keccak256(getBytes(encoded))` and from the golden hash.
  - Rejects invalid addresses, bad EIP-55 checksums, mismatched/empty arrays, negative/fractional/overflowing uint256, malformed/odd-length hex calldata, and malformed description hashes.
  - Cross-check reports matches/mismatches with provenance and always `authoritative: false`.
- `package.json`
  - Fixed a pre-existing syntax error in the `@anthropic-ai/sdk` dependency key that made `package.json` invalid JSON and blocked all Node/npm/tsc/jest commands. The corrected name matches `package-lock.json`.
